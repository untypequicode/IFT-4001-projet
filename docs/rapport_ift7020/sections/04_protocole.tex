\section{Protocole d'expérimentation}
\label{sec:protocole}

Cette section décrit le protocole expérimental pour comparer les deux modèles développés sur deux solveurs MiniZinc (Chuffed et Gecode).

\subsection{Instances du banc d'essai}

Huit instances de test ont été générées automatiquement avec un script Python, couvrant différentes tailles :
\begin{itemize}
    \item \textbf{Small :} 2 instances (small\_01 : 2 trains, 8 opérations ; small\_02 : 3 trains, 10 opérations)
    \item \textbf{Medium :} 3 instances (30 à 45 opérations, 5 à 7 trains)
    \item \textbf{Large :} 3 instances (60 à 90 opérations, 10 à 15 trains)
\end{itemize}

Toutes les instances ont un horizon de 24 heures (1440 minutes), des temps de setup de 10 minutes entre opérations et 30 minutes entre trains différents, et un mélange de maintenances urgentes et préventives.

\subsection{Métriques}

Pour chaque instance et chaque solveur, nous mesurons :
\begin{itemize}
    \item \textbf{Temps de résolution :} Temps total pour trouver une solution ou prouver l'insatisfiabilité (en secondes)
    \item \textbf{Statut :} Résolu, insatisfiable (UNSAT), ou timeout (> 300 secondes)
    \item \textbf{Qualité de la solution :} Valeur de l'objectif (retard pondéré) pour les instances résolubles
\end{itemize}

\subsection{Environnement}

Les tests sont effectués sur une machine Windows 11 avec un processeur Intel i7-11800H et 16 Go de RAM. MiniZinc version 2.9.4 est utilisé avec Chuffed 0.13.2 et Gecode 6.3.0. Le temps limite est fixé à 300 secondes par instance. Pour chaque combinaison instance-modèle-solveur (8 instances × 2 modèles × 2 solveurs = 32 combinaisons), les métriques sont collectées et enregistrées.
